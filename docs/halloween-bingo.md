## 同時抽選・5×5カード

`202610310001_live_bingo.sql` を先に適用する。既存の参加権・Slack告知は維持する。
主催者（既存主催者のSlack ID、かつAdmin）のみ、ビンゴ画面から開始・抽選・終了できる。
開始は全員の画面を開き、参加者・カード・投稿回数・ルールを確定する。開始後の再配布・リセットは提供しない。
参加権のないユーザーと主催者は観覧モード。参加権は開始時に確定し、それ以降の新規参加権は進行中のゲームには追加しない。

カードはB=1〜15、I=16〜30、N=31〜45、G=46〜60、O=61〜75の列、中央はFREE。
カードはDB保存し本人だけに返す。全員が同じ抽選履歴を取得し、当たったマス・リーチ・ビンゴは自動判定する。同じ球で達成した人は同着。
待機中は4秒、開催中は1秒間隔で同期する（非表示タブは15秒、復帰時に即同期）。
抽選受理から2秒後に共通の演出を開始、4.5秒後に発表。発表前の番号はAPIで返さない。
ネットワーク切断中は最後のカードを保持し、復帰時に履歴から復元する。バックグラウンドのブラウザは演出の全編再生ではなく現在の進行へ追いつく。

### 公開する日報応援ルール

主催者は開始前に「日報応援抽選」または「均等抽選」を選ぶ。ルールは参加者全員に表示する。
集計期間は日本時間2026/10/20 00:00以上、11/1 00:00未満の公開時刻。下書きは除外し、公開後アーカイブ分を含む。
参加資格の期間（10/30の宣言後〜11/6 19:00）とは異なる。集計値はゲーム開始時に固定する。
各参加者の加点は `min(4, max(0, 投稿回数 - 1))`、つまり2〜5回で段階的に増え、5回で上限。
未抽選の番号nの重みは `100000 + floor(15000 × nを持つ全員の加点合計 / (4 × 全カード数))`。
番号ごとの重みは最大15%増であり、当選確率自体が15ポイント増える意味ではない。共通番号なので他の参加者にも影響し、当選を保証しない。
均等抽選は全番号の重みを100000とする。乱数はサーバーの暗号学的乱数を使い、既出番号は候補から除外。
投稿回数とカードは本人だけに返し、他人の値は参加者APIに含めない。主催者を含めブラウザへ全カードを配らない。
管理・検証用にDBへ確定投稿回数・抽選ごとの重み・実行者を保存する。秘密の重み付けや監査記録の削除は行わない。

抽選はゲーム行ロック、期待する抽選回数、リクエストID、DBの番号一意制約で二重操作を防ぐ。抽選中の次球・終了は禁止。
検証用のローカルDBは空の専用DBを使用する：
`LIVE_BINGO_TEST_DATABASE_URL=postgres://USER@127.0.0.1:PORT/EMPTY_DB npx vitest run src/server/bingo-game.test.ts`
`npx playwright test e2e/halloween-bingo.spec.ts --project=desktop --project=mobile` は主催者・参加者の2ブラウザ同期を検証する。
